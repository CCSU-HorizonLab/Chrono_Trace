# Chrono Trace

> 面向微信聊天记录的本地分析与实时辅助工具。

[![Python](https://img.shields.io/badge/Python-3.8+-blue.svg)](https://www.python.org/)
[![Vue](https://img.shields.io/badge/Vue-3.x-green.svg)](https://vuejs.org/)
[![License](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

Chrono Trace 目前已经从“聊天记录导入工具”演进到一个可用的桌面端原型，覆盖了历史导入、关系分析、实时监听、AI 建议、悬浮辅助窗和多模型配置。项目仍在持续迭代，但主链路已经基本成型。

## 当前进度

### 已可用

- 微信 4.0+ 聊天数据库导入与解密
- 自动检测微信目录，也支持手动指定自定义路径
- 增量导入检测，减少重复导入成本
- 历史聊天分析页
- 关系洞察与好感度分析
- 实时监听单个联系人会话
- 实时情绪分析与触发式 AI 建议
- 悬浮窗模式，边聊边看建议
- LLM 模型配置与切换
- 联系人画像 / 自我画像生成

### 进行中但仍有限制

- 实时监听目前依赖 Windows 微信主窗口和项目内 `native_uia` 监听后端
- 当前只支持单对象实时监听
- 多媒体消息目前以“消息类型识别 / 计数 / 规则增强”为主
- 语音消息尚未打通转文字自动落库
- 表情相关目前支持 emoji/表情符号规则，尚未支持表情包图片内容识别

### 下一步计划

- 表情包识别
- 语音转文字并自动保存
- 更完整的多模态消息理解
- 实时建议链路继续稳定化

## 现在能做什么

### 1. 微信数据导入

- 支持微信 4.0+ 数据目录扫描
- 支持 `wx_key` 解密流程
- 支持联系人、会话、消息入库
- 支持导入基线记录和增量变化检测
- 支持自定义微信目录扫描

### 2. 历史分析

分析页已经不是早期的基础图表页面，目前包含：

- 情绪曲线
- 词云
- 会话时间线
- 响应时间分布
- 主动率分析
- 字数投入比例
- 活跃日历
- 关系信息补充
- 喜好关键词配置
- 四维好感度分析

当前好感度分析包含四个维度：

- 情感共振
- 聊天积极度
- 态度倾向
- 喜好兼容度

### 3. 实时建议

实时建议页现在已经是一个完整的“监听控制中心”，支持：

- 选择监听对象
- 开始 / 停止监听
- 监听状态轮询
- 断点恢复提示
- 启动前回溯补全
- 实时消息流展示
- 实时情绪分析
- 全自动 / 半自动 / 手动 三种触发模式
- 亲密 / 维持 / 疏远 三种意图
- 手动生成建议
- 查看 AI 使用的上下文

当前触发链路已经接入：

- 负面连续
- 情绪突变
- 敷衍回复
- 长时间沉默
- 积极窗口
- 话题降温

### 4. 悬浮窗辅助

悬浮窗模式已经落地，适合边聊边参考：

- 联系人画像摘要
- 实时图表切换
- 建议卡片展开/收起
- 一键复制话术
- 上次线程继续
- 快捷提示词
- 模型热切换
- 监听中断后的恢复与补全

### 5. AI 与模型配置

设置页已经支持多模型管理：

- OpenAI
- DeepSeek
- 智谱 GLM
- Moonshot / Kimi
- MiniMax
- Ollama
- 自定义兼容接口

支持：

- 多模型保存
- 激活模型切换
- 拉取 provider 模型列表
- 自动保存本地设置

## 当前技术架构

```text
Vue 3 + TypeScript + Vite
        |
    PyWebView Bridge
        |
Python Backend Services
        |
SQLite / 本地分析库
        |
微信 4.0+ 数据库 / native_uia provider
```

主要目录：

```text
backend/
  app/
    db/              # SQLite schema 与迁移
    services/
      analysis/      # 历史分析与好感度分析
      realtime/      # 实时监听、情绪分析、AI 建议
      wechat/        # 微信数据库扫描、解密、导入
    webview/         # 前后端桥接

frontend/
  src/
    views/           # Home / Analytics / Suggestions / Settings / FloatingPanel
    components/      # 图表、关系分析、基础组件
```

## 快速启动

### 环境要求

- Windows 10/11
- Python 3.8+
- Node.js 16+
- 微信 PC 4.0+

### 1. 安装依赖

```bash
pip install -r requirements.txt
cd frontend
npm install
cd ..
```

### 2. 启动开发模式

```bash
python app_dev.py
```

### 3. 生产模式

先构建前端：

```bash
cd frontend
npm run build
cd ..
python app.py
```

## 实时监听补充说明

实时监听默认走项目内 `native_uia` 主链路，用 UI Automation 读取微信主窗口的可见消息。仅做历史导入和分析时，不依赖这部分。

目前实时监听有这些约束：

- 仅支持 Windows
- 仅支持微信 PC 客户端
- 微信主窗口需要保持可见，不能最小化
- 仅支持单会话监听
- 监听目标名称需要和微信内显示一致
- 当前已验证微信 `4.0.5` 主窗口监听，`4.1.x` 仍在继续适配

## 使用流程

### 历史导入

1. 使用 `wx_key` 获取微信数据库密钥
2. 打开首页，输入密钥并验证
3. 自动检测或手动指定微信目录
4. 执行导入
5. 在分析页查看关系分析结果

### 实时辅助

1. 在设置页配置并激活一个可用 LLM
2. 打开建议页选择联系人
3. 开始实时监听
4. 按需切换触发模式和关系意图
5. 需要时进入悬浮窗边聊边参考

## 已知边界

- 当前大量深度分析仍以文本消息为核心
- 媒体路径字段已经预留，但媒体理解能力还不完整
- emoji 已参与实时情绪规则，但表情包图片语义尚未接入
- 语音消息类型已可识别，但还没有“转文字并自动保存”的完整流程
