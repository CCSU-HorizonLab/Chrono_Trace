# RAG 触发泛化优化方案：记忆意图层与双模式注入

## 1. 背景

当前 RAG 触发容易落到关键词判断：用户说到“记忆”“历史”“上次”等词时才更容易触发。这个方式不够自然，也不够泛化。

真实使用里，用户不一定会明确说“查记忆”。例如：

- 她上次说的什么流派我不知道
- 我们之前吃的那家店是啥
- 刚刚那个话题能接回去吗
- 给我一个相关建议

这些请求本质上都可能需要历史上下文、共同记忆或关系背景。RAG 不应该只服务“建议卡片”，也应该服务用户直接向 AI 提问的场景。

## 2. 核心目标

新增“记忆意图层”，把 RAG 触发从“关键词匹配”升级为“是否需要联系人级历史记忆”的判断。

目标：

- RAG 可以同时服务 `reply` 和 `suggestion`。
- 用户直接问 AI 时，如果问题需要历史记忆，也可以触发 RAG。
- 用户要求生成话术时，如果当前任务依赖共同记忆，也可以触发 RAG。
- 减少硬编码关键词，只保留少量高精度兜底信号。
- RAG 没命中时必须明确传递 no-hit 状态，禁止模型编造历史。
- 日志必须能说明：为什么触发、查了什么、命中多少、如何注入。

## 3. 设计原则

### 3.1 RAG 绑定记忆意图，不绑定输出形态

`reply` 和 `suggestion` 只是最终输出形态，不应该决定是否能使用 RAG。

推荐决策顺序：

```text
用户当前输入 + 最近上下文
  -> 判断是否需要历史/记忆/关系背景
  -> 如需要，构造 RAG query
  -> 执行联系人级检索
  -> 根据输出形态注入不同 prompt
  -> 生成 reply 或 suggestion
```

### 3.2 记忆意图模式

第一版定义 4 种模式：

| 模式 | 含义 | 是否检索 |
| --- | --- | --- |
| `none` | 当前输入不需要历史记忆 | 否 |
| `ambient` | 当前聊天可以轻量参考关系背景 | 可选 |
| `memory_request` | 用户明确或隐含要求查历史、共同经历、过去细节 | 是 |
| `relationship_context` | 用户需要判断关系策略、边界、对方习惯 | 是 |

### 3.3 输出结构

记忆意图检测结果建议统一为：

```python
{
    "should_retrieve": bool,
    "mode": "none" | "ambient" | "memory_request" | "relationship_context",
    "confidence": float,
    "query": str,
    "reason": str,
}
```

字段说明：

- `should_retrieve`：是否需要进入 RAG。
- `mode`：触发类型。
- `confidence`：触发置信度。
- `query`：用于检索的短查询，优先来自用户当前问题和最近上下文。
- `reason`：用于日志和调试，不进入最终用户可见回复。

## 4. 触发策略

### 4.1 不再依赖大词表

不建议继续扩展大量硬编码关键词。关键词越多，误触发越多，也越难维护。

推荐组合：

- 小型高精度规则：只识别非常明确的历史请求。
- 语义原型匹配：用少量代表性句子判断“是否像记忆请求”。
- 上下文继承：用户上一轮已经在问历史，本轮短句也继承记忆意图。
- 结构化信号：当前联系人是否有 ready 索引、最近是否有 RAG 命中、用户是否在追问细节。

### 4.2 语义原型

第一版可以维护少量原型，不维护大词表。

示例：

```text
她之前说过什么
我们上次聊到哪里
帮我找一下之前的记录
这个人平时怎么说话
我该按我们之前的关系怎么回
上次那个东西是什么来着
```

实现时将用户当前输入与原型做 embedding 相似度或轻量文本相似度。相似度高于阈值时触发 `memory_request` 或 `relationship_context`。

如果本地 embedding 不可用，允许退回轻量规则和结构化上下文，但不能崩溃。

### 4.3 上下文继承

用户多轮追问时，后续短句不一定包含明显记忆词。

例如：

```text
用户：找一下上次她说杀戮尖塔的记录
AI：没找到明确流派，只找到聊过杀戮尖塔
用户：那给我个相关建议
```

第二句“那给我个相关建议”本身不是记忆关键词，但应继承上一轮 `memory_request`，继续允许 RAG。

继承规则：

- 最近 2-4 轮内存在高置信 `memory_request`。
- 当前用户输入是追问、补充、要求建议、要求解释。
- 当前联系人没有切换。
- 未出现明确话题切换。

## 5. 双模式 Prompt 注入

### 5.1 直接回复用户

当用户是在问 AI，而不是要求生成可发送话术时，RAG 注入到“可用历史记忆检索结果”。

示例：

```text
【可用历史记忆检索结果】
检索状态：hit
来源范围：当前联系人
结果：
1. 2026-05-10 左右，对方提到最近在玩杀戮尖塔，但没有明确说具体流派。

要求：
- 直接回答用户问题。
- 可以说明查到了什么、没查到什么。
- 不要生成建议卡片，除非用户明确要求话术。
- 不要编造检索结果之外的历史细节。
```

### 5.2 生成话术建议

当用户要求“怎么回”“给建议”“给话术”时，RAG 注入到“联系人级共同记忆 RAG”。

示例：

```text
【联系人级共同记忆 RAG】
检索状态：hit
使用规则：
- 最近对话优先于共同记忆。
- 只使用和当前话题相关的记忆。
- 不主动提敏感记忆。

相关记忆：
1. 对方之前聊过杀戮尖塔，语气轻松，适合用游戏话题开头。
```

### 5.3 No-hit 防幻觉

检索为空时，也应显式注入 no-hit 状态，而不是完全不写 RAG 段。

示例：

```text
【历史记忆检索状态】
检索状态：no_hit
说明：当前联系人历史中没有找到和“杀戮尖塔流派”直接相关的可靠记忆。

要求：
- 不要声称记忆中找到了具体流派。
- 可以建议用户自然追问对方。
- 可以基于当前上下文生成保守话术。
```

这样可以避免模型自己说“记忆中没找到”，但实际系统没有检索过。

## 6. 日志与可观察性

每次建议或回复生成，至少记录：

- `memory_intent_mode`
- `memory_intent_confidence`
- `memory_intent_query`
- `memory_intent_reason`
- `rag_enabled`
- `rag_retrieved`
- `rag_hit_count`
- `rag_injection_mode`: `none / reply / suggestion`
- `rag_no_hit_guard`
- `rag_latency_ms`
- `rag_degraded_reason`

调试日志中应能直接看出：

```text
[RAG Intent] mode=memory_request confidence=0.86 query="杀戮尖塔 流派"
[RAG] retrieved hit_count=2 latency=121ms
[RAG] injected mode=reply no_hit_guard=false
```

或：

```text
[RAG Intent] mode=memory_request confidence=0.82 query="上次说的流派"
[RAG] retrieved hit_count=0 latency=98ms
[RAG] injected mode=reply no_hit_guard=true
```

## 7. 与现有链路关系

推荐新增独立模块，不继续把触发逻辑堆进 `llm_engine.py`。

建议职责：

- `memory_intent.py`：判断是否需要 RAG，输出 `MemoryIntent`。
- `rag_context_builder.py`：根据 `MemoryIntent` 构造检索上下文、no-hit guard 和注入模式。
- `rag_retriever.py`：只负责检索、重排、过滤，不负责判断用户意图。
- `llm_engine.py`：接收已构造好的上下文，把它拼入 reply 或 suggestion prompt。

## 8. 验收样例

| 输入 | 预期 |
| --- | --- |
| 她上次说的什么流派我不知道 | 触发 `memory_request`，执行 RAG |
| 找一下上次那家店我们吃的啥 | 触发 `memory_request`，执行 RAG |
| 我要你给出相关建议 | 如上文是记忆话题，继承 RAG；否则只生成普通建议 |
| 这个人现在适合开玩笑吗 | 触发 `relationship_context` |
| 你好，测试一下 | 不触发 RAG |
| 给我回一句 | 不强制触发 RAG，除非最近上下文需要记忆 |
| 她上次说的游戏是啥，但索引无结果 | 注入 no-hit guard，不编造 |

## 9. 第一版范围

第一版只解决 RAG 触发自然度和可观察性，不扩大到完整记忆编辑器。

包含：

- 记忆意图检测。
- reply/suggestion 双模式 RAG 注入。
- no-hit guard。
- 上下文继承。
- RAG 触发日志。
- 固定人工样例补充。

不包含：

- LLM 自动评分作为主验收。
- 跨联系人全局记忆混合。
- 复杂前端记忆编辑器。
- 训练或微调模型。
