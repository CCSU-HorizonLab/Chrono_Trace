# Goal: RAG 记忆意图触发优化

## 1. 目标

把当前 RAG 触发从“关键词硬编码”升级为“记忆意图层”。

优化后，系统应先判断用户当前输入是否需要历史记忆、共同经历或关系背景，再决定是否执行 RAG。RAG 不再只服务建议卡片，也可以服务用户直接向 AI 提问的 reply 场景。

详细方案见 [RAG 触发泛化优化方案](../rag-memory-intent-trigger-optimization.md)。

## 2. 成功标准

- RAG 触发不依赖大规模硬编码关键词。
- 用户直接询问历史、记忆、上次细节时，可以触发 RAG 并直接回答用户。
- 用户要求生成话术建议时，如果任务依赖共同记忆，也可以触发 RAG。
- 同一联系人内的连续追问可以继承上一轮记忆意图。
- 检索无结果时，prompt 明确包含 no-hit guard，禁止模型编造历史。
- 日志能追踪记忆意图、检索 query、命中数量、注入模式和降级原因。
- RAG 不可用时，原实时建议链路继续工作。

## 3. 非目标

- 不重写完整 RAG 架构。
- 不新增跨联系人全局记忆。
- 不训练或微调模型。
- 不引入复杂前端记忆编辑器。
- 不把 RAG 作为 reply 或 suggestion 的硬依赖。
- 不用 LLM 自动评分作为主要验收依据。

## 4. 用户体验原则

- 用户不需要知道“RAG”“token”“embedding”等概念。
- 用户只需要自然说“上次那个”“她之前说的”“给个相关建议”，系统就应尽量判断是否需要历史。
- 查到就基于历史回答或生成建议。
- 没查到就诚实说明，并给保守建议。
- 不因为 RAG 没命中而让建议生成失败。

## 5. 里程碑

### M1: 记忆意图定义

- 定义 `none / ambient / memory_request / relationship_context` 四种模式。
- 定义统一 `MemoryIntent` 输出结构。
- 明确各模式是否触发 RAG。

### M2: 触发判断优化

- 用小型高精度规则、语义原型和上下文继承替代大词表。
- 支持最近几轮对话中的记忆意图继承。
- 本地 embedding 不可用时，允许退回轻量规则和结构化信号。

### M3: 双模式注入

- direct reply 场景注入“可用历史记忆检索结果”。
- suggestion 场景注入“联系人级共同记忆 RAG”。
- 检索为空时注入 no-hit guard。

### M4: 可观察性与验收

- 日志记录 memory intent、query、hit count、injection mode。
- 固定人工样例覆盖记忆追问、建议追问、无关输入、no-hit 场景。
- 对比优化前后误触发率、漏触发率和 no-hit 诚实率。

## 6. 验收口径

完成后应能回答：

- 这次用户输入是否触发了记忆意图？
- 触发模式是什么？
- 生成的检索 query 是什么？
- 是否真的执行了 RAG？
- 命中了几条记忆？
- RAG 注入到了 reply 还是 suggestion？
- 如果没命中，是否注入了 no-hit guard？
- 模型是否避免编造历史细节？
