# Goal: RAG 化实时建议生成 v1

## 1. 目标

将 Chrono Trace 的实时建议从“最近对话 + 画像摘要 + prompt 规则”升级为联系人级共同记忆 RAG。

v1 的目标不是追求复杂知识库，而是先打通稳定闭环：

```text
联系人级索引 -> 检索与过滤 -> 脱敏/最小化 -> LLM 建议 -> 反馈归因 -> 样本回写
```

建议生成必须优先服务当前聊天和关系策略。用户表达风格、共同记忆和历史反馈都是辅助，不允许盖过最近对话。

详细设计以 [RAG 增量计划书](../incremental-plan-rag-suggestions.md) 为准。

## 2. 成功标准

- 每个聊天对象有独立 RAG 空间，按 `account_wxid + conversation_id` 隔离。
- RAG 第一版默认使用本地 embedding：`tingting0514/text2vec-base-chinese`，384 维。
- 远程 embedding 默认关闭，用户显式配置后才可使用。
- 远程 RAG 上下文脱敏默认开启；用户可在高级设置中关闭，但必须明确提示风险。
- RAG 检索、索引、脱敏、压缩失败时，不阻断原实时建议链路。
- 单次建议中 RAG 检索与上下文构造额外耗时默认不超过 800ms。
- 用户反馈不再只看下一条消息，而是通过归因窗口判断采纳、改写、铺垫、无关和被打断。
- 任意一次使用 RAG 的建议，都能追溯检索来源、索引状态、脱敏状态和是否降级。
- 固定人工样例集可稳定对比无 RAG 与有 RAG 的输出质量。

## 3. 非目标

- v1 不训练或微调模型。
- v1 不实现复杂可视化记忆编辑器。
- v1 不默认开启远程 embedding。
- v1 不默认跨联系人混合学习用户风格。
- v1 不把 RAG 作为实时建议硬依赖。
- v1 不改写 `messages.content` 或 `realtime_message_buffer.content` 原文。
- v1 不以 LLM 自动评分作为主要验收依据。

## 4. 用户体验原则

- 默认保护隐私，但允许高级用户显式关闭远程 RAG 脱敏。
- 关闭远程 RAG 脱敏时，界面必须说明未脱敏或弱脱敏上下文会发送给远程模型。
- 本地数据保留原文，远程请求默认使用脱敏和压缩后的最小上下文。
- RAG 是增强层：不可用时用户仍能获得原有建议能力。
- 共同记忆必须围绕当前联系人和当前话题，不做无关翻旧账。
- 建议卡片最终要能解释“参考了关系状态、共同记忆、表达习惯、反馈偏好中的哪些类型”，但不泄露长篇历史原文。

## 5. 里程碑

### M1: 数据与配置基础

- 新增联系人级 RAG 文档、向量、检索日志、索引状态相关数据结构。
- 新增隐私脱敏缓存和反馈归因相关数据结构。
- 设置默认 embedding 模型、隐私模式、远程 embedding 开关和 RAG 开关。

### M2: 联系人级索引闭环

- 支持联系人级懒加载索引。
- 支持后台增量索引队列。
- 支持 `pending / indexing / ready / stale / failed` 索引状态。
- embedding 模型、维度、隐私模式变化后能标记 stale 并按联系人重建。

### M3: 检索、脱敏与建议接入

- 生成建议前完成 RAG 召回、过滤、重排和上下文压缩。
- 远程请求默认使用脱敏 RAG 上下文。
- 关闭远程 RAG 脱敏时允许远程 LLM 使用未脱敏或弱脱敏 RAG，并记录风险状态。
- RAG 超时、索引失败、脱敏失败时按降级策略回退。

### M4: 反馈归因与学习

- 建议后的用户行为进入归因窗口。
- 支持多消息聚合，避免把铺垫误判为最终改写。
- 高置信 `accepted / rewritten / preface_then_reply` 回写为反馈样本。
- 低置信、无关、被打断反馈只记录日志，不污染 RAG。

### M5: 前端控制与样例评估

- 设置页展示 RAG 状态、索引数量、更新时间、占用空间。
- 支持联系人级启用、禁用、清空、重建索引。
- 支持远程 RAG 脱敏开关和风险确认。
- 建立固定匿名/脱敏人工样例集，用于回归评估。

## 6. 验收口径

v1 完成时，应能回答：

- 这个建议用了哪些 RAG 文档？
- 这些文档属于哪个联系人？
- 当前索引是否 ready、stale 或 failed？
- 是否触发了 RAG 超时或降级？
- 发给远程 LLM 的 RAG 上下文是否脱敏？
- 如果用户关闭了远程 RAG 脱敏，日志是否明确记录？
- 用户实际发送内容是否被正确归因为采纳、改写、铺垫、无关或被打断？
- 固定样例集中，RAG 输出是否比无 RAG 更贴近当前关系和当前上下文？
