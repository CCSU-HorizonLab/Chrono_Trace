# RAG v1 代码质量门禁

本文定义 RAG 化实时建议生成 v1 的合入标准。实现可以分阶段，但任何阶段都不能破坏这些底线。

详细目标见 [RAG v1 Goal](./rag-suggestion-v1-goal.md)，详细方案见 [RAG 增量计划书](../incremental-plan-rag-suggestions.md)。

## 1. 数据安全

- 不修改 `messages.content`、`realtime_message_buffer.content` 原文。
- 远程 RAG 上下文脱敏默认开启。
- 关闭远程 RAG 脱敏必须是用户显式操作，不能被隐式配置或异常路径触发。
- 关闭远程 RAG 脱敏后，远程 LLM 可接收未脱敏或弱脱敏 RAG，但必须记录 `redaction_disabled = true`。
- 远程 embedding 默认关闭；如果用户同时开启远程 embedding 且关闭脱敏，必须再次确认风险。
- 强敏信息进入默认远程上下文应视为阻断级问题。
- 敏感记忆默认不主动注入，只能在当前话题强相关且策略允许时进入候选。

## 2. 可靠性

- RAG 不能成为实时建议硬依赖。
- RAG 检索与上下文构造超过 800ms 必须降级。
- 索引不存在时应触发联系人级懒加载，本次建议可无 RAG 继续。
- 索引失败必须记录 `failed` 状态，并允许用户重试。
- `stale` 索引可以临时使用，但日志必须标记。
- embedding 模型缺失时，不能崩溃；应回退关键词/结构化上下文或无 RAG。
- 远程 embedding 失败不阻塞建议生成。
- 脱敏异常时只能发送强规则遮罩后的压缩摘要；遮罩失败则阻断远程 RAG 请求。

## 3. 数据一致性

- RAG 文档、向量、记忆、反馈样本必须按 `account_wxid + conversation_id` 隔离。
- 不同 embedding 模型或维度的向量不能混用。
- `rag_embedding_model`、`rag_embedding_dim`、`rag_privacy_mode` 变化后，相关索引必须标记 `stale`。
- 新索引构建成功前，不删除旧索引。
- 新索引失败时，旧索引仍可读，但状态和日志必须反映失败。
- 用户删除或禁用某联系人 RAG 数据后，该联系人记忆不得继续进入候选。
- `superseded` 记忆不得主动注入 prompt。

## 4. 反馈归因

- 不允许把建议后的下一条用户消息直接当作最终反馈。
- 必须通过时间窗口、会话窗口和多消息聚合做反馈归因。
- 用户先铺垫再正式回复时，应归因为 `preface_then_reply` 或对应有效类型。
- 对方插话或场景变化导致无法判断时，应归因为 `interrupted` 或低置信，不写入正向样本。
- `unrelated`、`interrupted`、低置信反馈不得进入 `feedback_example`。
- 反馈样本必须保留来源 suggestion、候选消息序列和置信度。

## 5. 代码结构

- RAG 检索、索引、脱敏、反馈归因、prompt 注入应分层实现，不继续把所有逻辑堆进 `llm_engine.py`。
- 数据库写入必须幂等，重复索引同一消息不应产生重复文档。
- 后台索引任务必须可重试。
- prompt 构造不能直接读取数据库，应接收已构造好的上下文对象。
- 远程请求前的脱敏/最小化应走统一服务，不能在多个模块各写一套临时规则。
- 日志中不能输出长篇原始聊天内容或强敏信息。

## 6. 测试要求

最低测试覆盖：

- 默认远程 RAG 脱敏开启。
- 关闭远程 RAG 脱敏后，远程 RAG 可用且日志标记 `redaction_disabled = true`。
- 远程 embedding 默认关闭。
- 联系人级索引懒加载。
- `pending / indexing / ready / stale / failed` 状态流转。
- RAG 超过 800ms 后降级。
- embedding 模型缺失时不崩溃。
- 脱敏失败和强遮罩失败时按策略降级或阻断。
- 用户先铺垫再回复不会误判为第一条消息改写。
- `sensitive` 记忆默认不主动注入。
- `superseded` 记忆不主动注入。
- RAG 关闭后原实时建议链路仍可工作。

## 7. 人工样例验收

固定匿名/脱敏样例集至少覆盖：

- 冷场续聊。
- 轻量安抚。
- 邀约。
- 解释和道歉。
- 争执降温。
- 共同记忆被当前话题唤醒。
- 敏感记忆不应注入。
- 用户先铺垫再正式回复。

每次改动 RAG、脱敏、prompt 或反馈归因后，应对比无 RAG 与有 RAG 输出。RAG 输出不得在关系策略、隐私安全、身份区分上劣于无 RAG。
