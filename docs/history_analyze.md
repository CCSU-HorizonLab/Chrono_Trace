# 历史记录好感度分析
## 指标
好感度（总）、态度、情感共振率、聊天积极度、喜好

## 具体操作
注：标蓝的参数为用户可设定

### 预处理
预处理阶段的目标是**一次遍历收集所有统计常量**，避免后续维度重复计算，确保 O(N) 复杂度。

**执行顺序**：

#### 1. 配置准备（开始前一次性完成）
- 用户给出聊天对象的标签（例如是同事还是好朋友）；
- 关键词列表准备（包括正面词汇、负面词汇、专属称呼、隐私分享关键词（如："秘密"）、节假日列表、共情关键词、安抚关键词、喜好关键词（需要用户提供喜好）等）；
  > **注**：用户可以在初始化后自定义添加关键词，系统支持动态扩展；

#### 2. 数据准备
- 各个聊天对象的有序消息列表（按时间排序）；

#### 3. 情感分析（批量处理）
- 对每条消息的情感分析（包括情感极性（积极1、中性0、消极-1）、强度分数（从-1（极度消极）到1（极度积极），中性接近0）、句向量）；
  > **优化**：使用批量处理（32条/批次）提升性能

#### 4. 会话划分（基于语义相似度）
- 根据话题延续性划分会话：用sentence-transformers库生成句向量，滑动窗口（窗口的消息条数可自己测试调整），记录所有相似度分数形成序列，找到"谷值"（如果相似度 < 阈值则标记为话题边界，阈值可测试调整），此外可以结合时间间隔辅助，如果时间间隔过高，即使相似度高也强制分割（可以根据用户给出的聊天对象标签不同有所不同）；
- **记录会话发起方**：每个会话的第一个消息的发送方即为该会话的发起方

#### 5. 构建交互对（一次遍历收集所有统计）
在此步骤中，遍历所有会话内的消息，同时完成以下操作：

**5.1 发言单位合并**
- 连续消息间隔 < 5分钟则合并为发言单位
- 记录发言单位包含的消息ID列表

**5.2 交互对构建**
- 从一方的发言单位到另一方的下一个发言单位形成交互对（双向都算）

**5.3 基础常量统计**（一次性遍历收集）
  ```python
  # 消息统计
  total_message_count           # 总消息数
  user_message_count            # 用户发送的消息数
  other_message_count           # 对方发送的消息数
  total_character_count         # 总字符数
  avg_message_length            # 平均消息长度
  long_text_message_count       # 长文本（>100字）消息数

  # 情感统计
  total_positive_count          # 积极消息数（极性=1）
  total_negative_count          # 消极消息数（极性=-1）
  total_neutral_count           # 中性消息数（极性=0）

  # 时间统计
  conversation_duration_days    # 聊天持续天数（首尾消息日期差）

  # 会话统计
  total_session_count           # 总会话数
  user_initiated_session_count  # 用户主动发起的会话数（来自步骤4）
  other_initiated_session_count # 对方主动发起的会话数（来自步骤4）

  # 交互对统计
  total_pair_count              # 总交互对数
  user_initiated_pair_count     # 用户主动发起的交互对数
  other_initiated_pair_count    # 对方主动发起的交互对数
  same_polarity_pair_count      # 同极性交互对数
  positive_positive_pair_count  # 积极消息互发对数
  negative_initiated_by_user_count # 用户发起的消极交互对数
  resolved_negative_pair_count  # 被化解的消极交互对数（检查回复极性+安抚关键词）

  # 态度倾向统计（一次遍历检查所有6类关键词）
  emoji_message_count           # 包含表情包的消息数
  voice_message_count           # 语音消息数
  video_message_count           # 视频通话消息数
  nickname_message_count        # 包含专属称呼的消息数
  privacy_message_count         # 包含隐私分享关键词的消息数
  holiday_message_count         # 节假日祝福消息数
  holidays_sent_count           # 实际发送的节假日数量（去重）
  preference_session_count      # 提及喜好的会话数（标记会话级别）
  ```

#### 6. 后处理统计
- 聊天对象高频回复时段（基于交互对的时间戳分布统计）

### 情感共振率维度（权重0.3）
**前提**：使用预处理阶段已构建的交互对和情感分析结果。

#### 参数（加实现方法）（权重）
- 双向积极情感响应率（积极消息互发数 / 总积极消息数）（20%）
  - 参数：
    - 总积极消息数（来自预处理：total_positive_count）；
    - 积极消息互发数（来自预处理：positive_positive_pair_count）。
- 情感极性一致性得分（双方同极性消息占比 × 语义相似度均值）（15%）
  - 参数：
    - 同极性消息占比（来自预处理：same_polarity_pair_count / total_pair_count）；
    - 语义相似度均值（只针对同极性交互对，用句向量计算余弦相似度（预存向量），取这些对的相似度平均值（如果无同极性对，设为0）。）
- 情绪强度匹配度（双方单条消息情感得分差值的绝对值均值的倒数）（10%）
  - 参数：
    - 差值绝对值列表（遍历所有交互对，对每对计算 |强度分数A - 强度分数B|，收集所有差值的绝对值列表。）
  - 处理：
    - 如果无交互对，设为0，mean_abs_diff = 所有绝对差的平均值，匹配度 = 1 / (mean_abs_diff + 0.1) （加0.1防除0），如果值>1，用 1 - tanh(mean_abs_diff) 夹到0-1。
- 共情意图识别率（包含共情关键词的消息数 / 总互动消息数）（30%）
  - 参数：
    - 共情消息数（遍历交互对统计包含共情关键词的消息数）（后续优化可以增加在回复我的情绪消息后加分，数据更准）；
    - 总互动消息数；
- 负面情绪协同化解率（化解回复 / 负面发起对）（25%）
  - 参数；
    - 负面发起对（来自预处理：negative_initiated_by_user_count）；
    - 化解回复（来自预处理：resolved_negative_pair_count）。

### 聊天积极度维度（权重0.3）
**前提**：使用预处理阶段已构建的交互对、会话和基础统计。

#### 参数（加实现方法）（权重）
- 日均聊天消息数（总消息数/聊天天数）（10%）
  - 参数：total_message_count / conversation_duration_days
- 回复及时率（20%）
  - 公式=在规定时效内回复的交互对数/需统计的交互对数*100%
  - 参数：
    - 规定时效（如五分钟、一小时、一天等，在这个时间段内回复才算及时回复）；
    - 及时回复的交互对数（遍历所有交互对，如果回复时间间隔 ≤ 规定时效，计为及时回复）；
    - 需要统计的总交互对数。
- 单条消息平均长度（10%）
  - 参数：avg_message_length（来自预处理）
- 长文本（超过100字）占比（15%）
  - 参数：long_text_message_count / total_message_count
- 话题延续性得分（基于语义相似度）（20%）
  - 参数：时窗（让用户根据聊天对象习性进行设置，话题延续性得分会根据时窗来划分聊天记录们进行延续性判断，保底为一天）
  - 根据时窗划分预处理阶段已经得出的会话，向上取整（就是只要这个会话包含时窗内的消息，就把这个会话算进来），分别计算每个会话内部的话题延续性得分，然后取平均分，再得出时窗内的话题延续性平均分，最后得出记录总体的话题延续性得分
- 主动发起聊天次数占比（25%）
  - 公式=对方主动发起会话次数/总会话数
  - 参数：
    - 对方主动发起会话次数（来自预处理：other_initiated_session_count）；
    - 总会话数（来自预处理：total_session_count）。
  - **简化说明**：预处理阶段已记录每个会话的发起方（基于语义相似度和时间间隔划分会话时记录第一个消息的发送方），无需复杂两步判定，直接使用会话发起方统计即可。

### 态度倾向维度（权重0.2）
**前提**：使用预处理阶段的一次遍历统计结果，避免 O(6N) 复杂度。

#### 前提准备：总消息数（分母常用）
- 正面词汇出现频次（总正面词汇出现消息数/总消息数）（如 "哈哈"" 谢谢 ""想你"）（25%）
- 负面词汇出现频次（总负面词汇出现消息数/总消息数）（反向扣分20%）
- 表情包 / 语音 / 视频通话使用占比（总表情包/语音/视频通话出现消息数/总消息数）（10%）
  - 三个互动类型的权重为：0.3：0.2：0.5
  - 参数：使用预处理阶段的 emoji_message_count, voice_message_count, video_message_count
- 专属称呼使用频率（昵称、外号）（总专属称呼出现消息数/总消息数）（25%）
  - 参数：使用预处理阶段的 nickname_message_count
- 隐私内容分享比例（总隐私内容分享关键词汇出现消息数/总消息数）（20%）
  - 参数：使用预处理阶段的 privacy_message_count
- 节假日祝福发送情况（总节假日祝福出现消息数/总消息数）（10%）
  - **优化公式**：holidays_sent_count / total_holiday_count
  - **说明**：使用实际发送的节假日数量（去重）除以总节假日数量，而非除以总消息数，更准确反映节假日覆盖率。
  - 参数：使用预处理阶段的 holidays_sent_count

### 喜好维度（权重0.2）
- 话题提及频率（提及喜好的会话次数/总会话数）（40%）
  - 参数：
    - 提及喜好的会话次数（来自预处理：preference_session_count）；
    - 总会话数（来自预处理：total_session_count）；
- 喜好话题延续性得分（基于语义相似度，判断是否与你喜好相同）（60%）
  - 遍历所有提及喜好的会话，计算该会话内的延续性得分，最后的出所有提及喜好的会话的平均延续性得分
