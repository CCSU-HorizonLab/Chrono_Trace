## 待实施：情感分类器自蒸馏（RBT3 学生）

**状态**：已排期，未开工。

**问题**：sentiment_3class 是 BERT-base 级（~102M），预处理阶段对每条文本
消息跑一次分类，13 万条会话耗时仍是长杆（bge 只加速了嵌入侧）。

**方法**：
1. 学生模型选 RBT3/RBTL3（哈工大 3 层中文 RoBERTa，多数中文分类任务
   损失很小）或 TinyBERT-4 层中文版（两阶段蒸馏，文献保教师 96.8% 性能）。
   ALBERT-tiny 慎选（同效果下可能更慢、精度折损大）。
2. **零标注成本蒸馏**：教师=sentiment_3class 现役模型；训练数据=
   sentiment_cache 已积累的 25.9 万条真实消息的极性/强度缓存（以及
   realtime_sentiment_cache 的软标签可加 logit 蒸馏温度项）。
3. 导出 ONNX fp16 走现有 `export_models_onnx.py`；挂载点复用
   `_load_realtime_service` 的分类器接口；变体机制照抄 bge 的做法
   （settings 键 + 目录缺产物回退）。
4. 验收：在 5000 条真实消息上与教师对比极性一致率 ≥97%、强度 MAE 足够小；
   CPU 吞吐 ≥3×（3 层模型理论 3-4×）。

**预期效益**：情感分类 3-5×；丰瑶级预处理从 ~30-40 分钟压到 **~15 分钟内**。

**参考**：TinyBERT 论文（7.5× 小 / 9.4× 快 / 96.8% 性能）；
ymcui/Chinese-BERT-wwm（RBT3 效果表）。

## 待验证：OpenVINO Execution Provider

**状态**：仅调研，未实施。**先做评估脚本再决定是否引入依赖。**

**问题**：本机 CPU（Intel i7-8665U）上 ORT 默认 CPU EP 之外，OpenVINO EP
对 BERT 类负载文献报告 2-3×（个别 10×）加速；代价是 +50MB 级依赖、仅
Intel 受益。

**方法**：
1. 临时环境装 `openvino`（不入运行时依赖），评估脚本对 bge-small
   fp16 模型分别用 ORT-CPU EP 与 OpenVINO EP 跑同一批真实消息
   （复用 ④ 的基准脚本骨架：同 batch、同文本、动态 padding）。
2. 校验向量一致性（两 EP 输出 cosine 应 ≈1.0）。
3. 若加速 <1.5× 或向量有偏 → 弃；若 ≥2× → 评估 openvino 包体积与
   Windows 打包兼容性（DirectML GPU 变体不受影响），再决定以可选
   变体接入（`resolve_providers` 加一档）。

**预期效益**：不确定性最大的一项，文献区间 2-3×；叠加 bge 后可能把
嵌入推向 100 条/s 量级。**AMD 机器无效**（本机恰为 Intel 才值得试）。
