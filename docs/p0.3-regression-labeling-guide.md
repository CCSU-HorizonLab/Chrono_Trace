# P0.3 人工建议回归集——标注流程指南

单人开发适配方案（改造计划 P0 修订说明）：同一标注者隔 ≥48 小时两轮独立标注，
自一致率 ≥0.70 为门槛；不一致样本记录仲裁理由后定标。

## 1. 挖掘

```bash
cd backend
../.venv/Scripts/python.exe scripts/mine_regression_scenarios.py --days 60 --limit 100
```

- `retrieval_log` 源：真实建议生成时刻（含 gate 决策与当时使用的策略 ID）。
- `memory_reference` 源：聊天中引用过去的消息（"还记得/上次/之前说过"），是"本应使用记忆"的时刻。
- 输出 `backend/data/regression_scenarios.jsonl`，文本已 strong_mask 脱敏；补充特征词用 `--extra-terms`。

数据到量判据：建议+检索日志+「不准确」点击合计 ≥100 条后，把目标集规模定为 60–100 条
（每联系人至少 2–3 个真实失败案例）。

## 2. 标注 schema（labels 字段）

| 字段 | 取值 |
|---|---|
| scene | ambient / manual_request / direct_reply / memory_lookup |
| need | no_memory / shared_memory / relationship_state / preference_avoid / user_style |
| relationship_stage | 自由文本（如"暧昧试探/高频互动"） |
| allowed_to_cite | 允许引用的范围（自由文本） |
| must_avoid | 应避免引用/敏感内容（自由文本） |
| should_followup | 无命中时应追问（true/false） |
| gold_fact_ids | 数字 fact ID 列表（校验联系人/会话范围） |
| gold_policy_ids | 关系策略 state / 偏好槽 pref ID 列表 |
| notes | 自由备注 |

每条至少含一项人工关系标签（relationship_stage/need）和一项可发送性判断
（allowed_to_cite 或 should_followup）。

## 3. 两轮自一致性

1. 第 1 轮：对全部候选独立标注，产出 `round1.jsonl`（在 labels 里填值，标注者不看第 2 轮前的任何汇总）。
2. 隔 ≥48 小时，第 2 轮：打乱顺序重新标注同一批，产出 `round2.jsonl`。
3. 一致率 = 两轮 scene+need+should_followup 完全一致的样本占比；≥0.70 通过。
4. 不一致样本：逐条记录仲裁理由（标注者自查上下文后定标），与两轮原标注一起归档
   `arbitration.jsonl`。标注轮次与分歧记录随数据集版本存档，不得覆盖历史样本。

## 4. 度量口径

在标注定标集上跑三臂（no-RAG / fact-only / +relationship&preference policy）：

- Recall@5 / MRR（检索）、触发 recall、正确注入率、证据使用率；
- 关系状态正确率、偏好/雷点遵守率（P1.2 的核心验收）；
- 误提旧事率、建议可发送率、no-hit 诚实率；
- 安全：敏感阻断 precision/recall、隔离率。

LLM 自动评分只做发现回归的辅助，不得单独作为通过条件（全局红线）。
