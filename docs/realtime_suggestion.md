# 实时 AI 建议生成

## 目标
在用户监听微信实时聊天时，根据对方的情绪变化**半自动**推送话术建议，帮助用户更好地把握对话节奏。

## 当前实现说明
- 监听后端统一为项目内 `native_uia`
- 统一通过 realtime provider 抽象读取微信主窗口可见消息
- 项目中保留 `wxauto4` 名字兼容入口，但底层实现同样指向 `native_uia`

## 已有基础
- **消息抓取**：`native_uia` provider 每 1 秒轮询可见消息列表，去重后存入 `realtime_message_buffer` 表
- **情感分析**：每条消息保存后立即用 RoBERTa-small 分析，输出极性(-1/0/1)、强度(-1.0~1.0)、置信度(0~1)，存入 `realtime_sentiment_cache` 表
- **规则增强**：表情符号、网络用语、否定词、反讽、敷衍检测等规则库
- **前端展示**：`Suggestions.vue` 已有监听控制 + 消息列表 + 情感标签显示

## 缺失环节（本模块要做的事）

### 1. 情绪状态追踪
> 当前是逐条分析，缺少"连续多条消息的情绪走势"概念

**滑动窗口**：维护对方最近 N 条消息的情感结果，聚合为当前对话情绪态势。

参数（可调）：
- 窗口大小：默认 5 条（只计对方消息）
- 聚合方式：加权平均（越近的消息权重越大）

### 2. 触发条件检测
> 什么时候应该给建议？不能每条消息都弹

| 触发类型 | 条件 | 冷却时间 | 严重度 |
|---------|------|---------|--------|
| 连续消极 | 对方连续 ≥3 条 polarity=-1 | 2分钟 | 高 |
| 情绪突变 | 窗口前半正面、后半负面 | 3分钟 | 高 |
| 敷衍回复 | 对方连续 ≥3 条消息长度 <5 字 | 5分钟 | 中 |
| 长时间不回 | 对方超过 10 分钟未发消息 | 10分钟 | 中 |
| 积极窗口 | 对方连续 ≥3 条正面且强度>0.5 | 5分钟 | 低 |
| 话题冷场 | 最近 5 分钟消息频率下降 50%+ | 5分钟 | 中 |

**冷却机制**：同一类触发在冷却时间内不重复触发，避免打扰。

### 3. 建议生成引擎
> 检测到触发后，生成什么内容？

采用**抽象层设计**，支持多种引擎切换：

#### 阶段一：规则模板引擎（默认）
- 基于 **触发类型 × 发展走向** 匹配预设建议模板
- 6 种触发 × 3 种走向（亲密/维持/疏远）= 18 套模板
- 每套模板包含：建议摘要 + 2~3 条具体话术
- 延迟 <10ms，不依赖任何外部服务
- 适合快速上线、跑通链路

#### 阶段二：LLM 引擎（后续扩展）
- **本地方案**：Ollama + Qwen2.5（隐私优先，需 GPU）
- **云端方案**：DeepSeek / GPT API（效果优先，需网络）
- 将实时消息上下文 + 情感分析结果 + 发展走向构造为 Prompt
- 用户可在设置中选择引擎类型

### 4. 建议推送与呈现
> 建议生成后，如何不割裂地呈现给用户？

**交互方式：半自动**
- 触发条件满足 → 右侧面板出现提示卡片（不弹窗、不打断）
- 用户点击提示 → 展开建议详情（摘要 + 话术列表）
- 用户也可以随时手动点击"生成建议"获取当前分析

**前端布局：左右分栏**

```
┌─────────────────────────────────────────────────────┐
│ [实时监听控制条] (全宽)                                │
├──────────────────────────┬──────────────────────────┤
│                          │                          │
│  📱 实时消息流            │  💡 AI 建议面板           │
│  - 消息气泡 + 情感标签    │  - 情绪态势指示           │
│  - 自动滚动到最新         │  - 触发提示卡片（半自动）  │
│                          │  - 建议详情展开           │
│                          │  - 发展走向选择           │
│                          │  - 手动请求建议按钮        │
│                          │                          │
└──────────────────────────┴──────────────────────────┘
```

> **注**：窄屏幕时自动切回上下布局

## 完整数据流

```
native_uia / provider 抓取消息
    ↓
保存到 realtime_message_buffer
    ↓
RoBERTa 情感分析 → 存入 realtime_sentiment_cache
    ↓
情绪状态追踪器（滑动窗口更新）
    ↓
触发条件检测（6 种条件 + 冷却机制）
    ↓ 满足触发
建议引擎生成（模板匹配 / LLM 推理）
    ↓
存入 realtime_suggestions 表
    ↓
前端轮询获取 → 右侧面板显示提示卡片
    ↓ 用户点击
展开建议详情（摘要 + 话术）
```

## 发展走向说明
用户在开始监听前或监听过程中选择对当前聊天对象的发展走向：

| 走向 | 说明 | 建议风格 |
|------|------|---------|
| 亲密 | 想拉近关系 | 热情关心、主动表达、制造话题 |
| 维持 | 保持现状 | 礼貌得体、适度回应、不冷不热 |
| 疏远 | 想保持距离 | 简短回复、不主动延伸、礼貌收尾 |

> **注**：发展走向直接影响建议引擎的输出内容，同一个触发在不同走向下给出的话术完全不同。

## 用户可配置参数

### 触发模式（核心设置）

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| **全自动** | 每条消息都分析，每次都给建议 | 新手用户、不确定怎么聊的时候 |
| **半自动**（默认） | 仅在触发条件满足时给建议 | 日常使用，不想被频繁打扰 |
| **纯手动** | 只有用户主动点击"生成建议"才给 | 有经验的用户，偶尔参考 |

> **注**：三种模式下，情绪状态追踪始终在后台运行（不影响性能），区别在于**是否主动推送建议**。

**全自动模式**下：
- 每条对方消息都触发建议生成
- 建议面板持续更新，展示最新分析
- 可设定更新频率上限（如最快每 10 秒更新一次）避免过于频繁

**半自动模式**下：
- 只在满足触发条件（见上表）时推送建议卡片
- 用户点击卡片后展开详情
- 可单独开关各触发类型、调整冷却时间

**纯手动模式**下：
- 不主动推送任何建议
- 情绪态势指示器仍然工作（用户可以看到情绪趋势）
- 用户随时可点击"生成建议"获取当前情况的分析

### 其他参数
- 滑动窗口大小（默认 5）
- 各触发类型的开关（半自动模式下有效）
- 冷却时间（默认值如触发条件表）
- 全自动模式更新频率上限（默认 10 秒）
- 建议引擎类型（模板 / 本地LLM / 云端API）
- 云端 API Key（如选用云端引擎）

## 隐私说明
- **默认模式（模板引擎）**：所有数据完全在本地处理，不联网
- **云端模式（可选）**：仅在用户主动启用时，将对话摘要发送到 API，用户可随时关闭
