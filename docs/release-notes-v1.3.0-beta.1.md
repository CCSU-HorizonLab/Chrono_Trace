# Chrono Trace Beta 1.3 发布说明

**版本**:v1.3.0-beta.1 ｜ **日期**:2026-09-30 ｜ **上一版本**:v1.2.0-beta.1(2026-09-27)

本版共 46 项提交,三条主线:**推理栈切换 ONNX/DirectML(GPU)**、**G1 建议生成闭环**(任务路由/知识装配/审计)、**记忆检索可靠性**;另有界面体验与消息解析增强。

## 推理栈:ONNX + DirectML(GPU)

- 情感分析与嵌入向量推理切换到 ONNX fp16 单后端:模型体积 1.17GB→409MB,运行栈内存 ~890MB→105MB,产物与原 torch 结果全等(cosine=1.0);移除 torch 回退。
- **Windows GPU 走 DirectML**(免 CUDA,系统内建);依赖统一为 `onnxruntime-directml`,N 卡设备自动启用(如 RTX 4060 实测 `device=dml`),无独显/异常时自动回退 CPU。
- 打包版自动下载源模型并导出 fp16 内置;开发机用 `backend/scripts/export_models_onnx.py` 一次性导出。
- 设置页展示当前 ONNX/DirectML 运行状态。

## 建议生成闭环(G1)

- **任务路由三元组**:用户输入拆分为 任务类型(记忆问答/回复建议/邀约策划/关系讨论/普通问答)× 输出形式 × 知识需求。"我想约她打游戏"进入邀约并给可发送话术;"我们玩过什么游戏"进入记忆问答直接回答,不再强行注入建议风格;显式追问("没有建议么")继承上一轮任务。
- **统一联系人上下文**:手动/自动/开场/全自动入口共用同一装配函数,绑定稳定 `account_wxid + conversation_id`;同名联系人拒绝自动选取;范围缺失时安全降级为通用帮助,不注入历史知识。
- **近期对话净化**:转账/收款/红包分类为事件行(不伪装成发言、不占窗口名额),系统通知剔除;"我明天给你转账"等正常聊天保留;纯通知窗口不再被解读成冷淡。
- **输出契约层**:资金往来不得用作关系结论的证据、直答必须有不空洞的 reply、要话术的任务不得空话术——违规自动修复重试并留痕。
- **关系信号块**:好感分析带时间/数据量/置信度注入,显式列出"不能推出的结论"(聊天多≠亲密、分数不授权推进关系、资金事件不反映态度)。
- **发送审计**:`request_id → suggestion_id → retrieval_log_id` 关联链,实际发送清单(fact/policy/偏好 ID、prompt hash、排除原因)入 `rag_retrieval_logs`;前端"已参考"badge 只依据实际发送。

## 记忆检索可靠性

- **冷启动自愈**:embedding 懒加载失败不再锁死进程(模型就位即重试);检索器遇冷自动后台预热;监听启动即预热——首问不再因向量分缺失丢事实。
- **零向量防线**:模型零向量输出按不可用处理不再落库;回填把零范数视为缺失自动重灌(修复了 ONNX 故障窗口期写入的 199 条零向量导致的检索静默失效)。
- 事实向量回补入口与诊断工具链:三链回放器(no_rag/legacy/g1)、NLI 忠实度判定、按联系人回滚脚本(dry-run 默认)。

## 界面与消息解析

- 悬浮窗双通道头像气泡与仿微信引用渲染;记忆依据弹窗直接复用 RagFactDialog 并展示证据消息原文与反馈状态。
- 消息时间标签解析增强:支持时段前缀(凌晨/早上/晚上等)、星期、"2026年9月29日"带年份等变体;时间气泡正确归为系统消息,不再混入聊天窗口。
- 修复捕获日期被当作对象信息显示的问题。

## 升级须知

- **开发环境**需重装依赖:`pip install -r requirements.txt`(onnxruntime→onnxruntime-directml),并运行一次 `backend/scripts/export_models_onnx.py` 导出 fp16 模型,否则情感分析与记忆检索不可用。
- 打包版内置模型,无需手动操作。
- 若升级前经历过推理报错,首次启动会自动重试加载并后台回灌缺失向量;仍异常时用"重建记忆索引"触发全量回补。
