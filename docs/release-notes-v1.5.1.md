# Chrono Trace v1.5.1 发布说明

**版本**:v1.5.1(修复版) ｜ **日期**:2026-10-16 ｜ **上一版本**:v1.5.0(2026-10-16)

纯修复版,共 5 项提交。最重要的:**修复打包版 RAG 记忆恒为 0 的缺陷**。

## RAG 记忆链路(核心修复)

- **词表随包**:1.5.0 打包产物漏带 `fact_kind_hints.json` / `fact_quality_patterns.json` 两份词表,而质量门按「缺失安全降级空表」设计静默放行——kind 信号词全空导致影子事实全部被 `unknown_kind` 拦截,**打包版构建任何联系人都 0 条记忆且无任何报错**(开发版词表就在源码旁,不可复现)。双平台 spec 补 datas 并对齐冻结态模块布局(`_internal/backend/app/...`);词表缺失时质量门改为 WARNING 留痕(本缺陷正是靠它现场定位),不再静默。
- **升级须知**:从 1.5.0 升级且已构建过索引的联系人**不会自动补出记忆**(无新消息时走增量跳过直接标记就绪)——需在「设置 → 联系人记忆」中「清空」后「构建」,触发全量重建。
- **已建索引联系人优先可见**:状态列表原按会话时间排序 + LIMIT 截断,会把建好记忆的低频联系人挤出列表(2000+ 联系人时「已就绪」徽标数与列表对不上、自动构建完成的联系人在列表中消失);改为已建索引者优先展示。

## 分析正确性

- **关系评估解析失败自动重试一次**:本地模型偶发不吐 JSON 致 LLM 维缺席,同输入重跑即恢复;失败留 WARNING 现场(内容长度/思考段长度/finish 原因/前 200 字)便于排查。
- **先热后冷文案方向感知**:近期日均高于早期时不再误写「降幅 -14%」类自相矛盾表述;未见异常级改配中性说明,不再挂「可能正在退潮」告急话术。

## 设置页

- 记忆状态摘要重排:「已就绪」改统计样式与「条记忆/占用」同款展示,构建中徽标与刷新按钮同行。
