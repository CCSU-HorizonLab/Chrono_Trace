# Chrono Trace v2.3.1 发布说明

**版本**:v2.3.1(功能版) ｜ **日期**:2026-11-08 ｜ **上一版本**:v2.2.2(2026-10-29)

一条主线:**情感引擎 v2 换代**(LLM 教师蒸馏、单句判断升级为上文口径、模型产物随 git 仓库分发、打包链去 modelscope 依赖)+**分析提速与渐进式展示**(本地四维秒级可看、AI 评估后台补齐、推理链四项向量化/去重)。外加**压缩消息数据修复**(zstd 解压找回长文本)、**问问微信记忆强化**与**四轮死代码清理收官**。共 35 个提交。

## 情感引擎 v2:从单句判断到上文口径

- **上文口径**:情感分类输入由单条消息升级为「前 3 条同会话上文 + 本条」——「嗯」「随便」这类语境依赖短句不再被误判;训练与实时/离线/补算全链消费同一口径模块,`ctx_used` 记录分析时的上文指纹,增量乱序回填致指纹漂移自动重算;
- **LLM 教师蒸馏**:Qwen3.5-9B 打标 68000 条,蒸馏 hfl/rbt3 学生(38M 参数,fp16 ONNX 74MB,较 v1 的 196MB 大幅瘦身);留出集对教师一致率 0.8616、推理加速约 4 倍;验收数据与已知限制(neg 召回偏弱等)归档于 `docs/analysis/sentiment-v2-acceptance.md`,采纳决定有据可查;
- **模型分发换代**:发行产物(onnx + tokenizer + `model_version.json` 代际档案)随 git 仓库分发,clone 即得免下载;export 门 fail-loud——缺代际档案拒绝导出,杜绝旧模型混入新代码;换蒸馏走 `regen_sentiment_model.py` 一条龙(本机数据采样→打标→训练→安装→导出→同步代际 tag);
- **换代失效链补全**:好感趋势 caliber 6 / 预处理算法 v3 / 时光深度 v6 版本常量联动 bump,实时情感缓存 purge 收敛单点——v1/v2 跨代数据不混口径;
- **有据弃用**:分类器 int8 动态量化经门槛验收(argmax 一致率未达 ≥98%)弃用;ORT 离线优化器实测负优化弃用,结论留档;嵌入 text2vec 变体与回退链移除,收敛 bge 单模型(-331 行);ModelScope 运行时下载链与打包依赖移除(发布产物不再捆绑 modelscope 包,Windows 安装包因此瘦身约 20MB+)。

## 分析提速与渐进式展示

- **本地与 AI 两阶段**:全面分析拆为两段——本地四维(互动投入/情感共鸣/亲近信号/喜好兼容)秒级完成即落库可看,AI 关系评估(实测单次约 100 秒)后台补齐,总分小幅更新;不再为等一次远程调用空转全程;
- **渐进渲染**:分析期间部分结果边出边看,「AI 评估中」徽标 + 占位卡,可跳过可取消,切联系人/重启后接续;
- **推理链四项优化**:嵌入热路径向量化消除逐元素装箱(会话切分相似度大头)、情感跨批文本去重(实测文本重复率 20.9%)、采样路径相似度向量化、推理批大小与线程调参。

## 数据修复:压缩消息找回

- **zstd 真解压**:微信 4.x 压缩通道消息(29~352 字长文本,实测占 4.7%)此前入库为「[压缩消息]」占位符——导入/监听链路现在真解压,存量数据用 `repair_compressed_messages.py` 一次性回填;
- **repair 派生层失效补全**:原地修复后按会话打脏并清理词云/预处理统计/RAG 派生层六表,缓存不再对内容变化失明(策略层用户可编排数据保留)。

## 问问微信(智能问答)与长期记忆

- 问答升级流式打字机输出与错误内联提示;RAG 检索覆盖率因子门控(双阈值),LLM 失败降级直出不再卡死;
- **记忆事实演变链时间线可视化**,失败事实可重试抽取;「不准确」反馈下渗两级漏斗参与融合决策;
- **参考记忆溯源就地纠错**:引用来源可直接修正,配竞态守卫;字面门控分词结果缓存,记忆问句低置信静默;
- LLM 连接收敛单源:取消代际统一、流内错误识别;基线预热静默时钟截断修复。

## 升级须知

- 模型换代后首次启动会自动作废两张情感缓存并按 v2 口径重算;好感趋势因 caliber 6 与历史不跨代比较属预期行为;
- 旧库无兼容迁移(项目约定):缺列报错时删除 `chrono_trace.db` 重导即可;
- 首次运行 `repair_compressed_messages.py --dry-run` 可预览压缩消息找回量。
